# Documentation

This repository is classified as `cli-tool` under the canonical standard. The
engineering contract for that type is `standards/repository-types/cli-tool.md`
in `soobujmiah/skb`.

## Documentation areas for this type

| Directory | Contents |
|---|---|
| `product/` | What the project is for, who it serves, and its current state |
| `architecture/` | Structure, boundaries, and the reasoning behind them |
| `development/` | How to build, run, and contribute |
| `testing/` | What is tested, how, and what is deliberately not covered |

A directory exists only when it holds real content. Empty directories are not
created to satisfy a checklist.

## What exists here

- [`ANDROID_ARM64_NATIVE_BUILD_GUIDE.md`](ANDROID_ARM64_NATIVE_BUILD_GUIDE.md) — reproducible native build and APK validation procedure.
- [`ON_DEVICE_ADB_SHIZUKU_OPERATIONAL_DEPENDENCY.md`](ON_DEVICE_ADB_SHIZUKU_OPERATIONAL_DEPENDENCY.md) — operational dependency audit.
- [`REAL_DEVICE_BUILD_VALIDATION.md`](REAL_DEVICE_BUILD_VALIDATION.md) — canonical physical-device evidence.
- [`TECHNICAL_REFERENCE.md`](TECHNICAL_REFERENCE.md) — architecture, tool roles, install model, and version boundaries.
- [`TERNUX_RELATIONSHIP.md`](TERNUX_RELATIONSHIP.md) — project boundary and cross-project qualification.
- [`SEO.md`](SEO.md) — site search/indexing review.
- [`validation/`](validation/) and [`assets/`](assets/) — dated evidence and diagrams.
- [`index.html`](index.html) — documentation website source.

## Rules

- Maintain this index when a documentation area is added, removed, or renamed.
- Operational state (build/test status, phases, current progress) is generated by
  the repository's own tooling and is read from `.repo/STATUS.md`; it is not
  restated as prose here.
- Decisions are recorded as ADRs under `docs/adr/` where the type requires them,
  using the format in `standards/repository-research-and-adr.md`.
