ARM64 Android Development Toolchain

Android development on Linux ARM64 —
without an x86_64-only Studio.

ADT provides a practical Android and Flutter toolchain for Linux ARM64 environments, including Termux + PRoot Debian on ARM64 Android devices. An ARM64 machine can prepare, build, sign, install, inspect, debug and validate Android applications. The CLI toolchain is the canonical path; GUI/X11 support is optional.

Capabilities

Tools that only need a JVM execution path are treated as architecture-independent at the Java level; everything else is a native aarch64 binary, built from source, or shimmed and documented as such.

01 SDK build-tools

ARM64-native aapt, aapt2, aidl, zipalign and related tools, built from AOSP source for linux-arm64.

02 Platform-tools

ARM64-native adb, fastboot and related platform tools.

03 Host toolchain

GCC/Clang, CMake, Ninja and Make for native builds, with Git and source-management tooling.

04 JVM tool paths

Java/JDK plus apksigner, d8 and R8 through their JVM execution paths.

05 Flutter & Dart

Flutter and Dart alongside Android SDK platforms for application builds.

06 Offline artifacts

Reusable ARM64 binary artifacts for expensive builds, so a setup does not have to rebuild from source every time.

Support discipline

A tool is not marked as supported simply because it exists upstream. Each important tool is classified by how it actually runs:

1 Native Linux ARM64 binary

2 Android/Termux binary

3 JVM-based, architecture-independent

4 Source-built ARM64 binary

5 Compatibility shim / workaround

6 Installed but not yet validated

Install

The one-line installer fetches the repository and runs the bootstrap — device check, host dependencies, tools, shims, SDK manager and platform, environment, then verification. It is idempotent: re-running updates an existing clone (fast-forward only) and skips what is already installed. 

# one-liner (fully automatic, no prompts)
curl -fsSL https://raw.githubusercontent.com/soobujmiah/adt/main/install.sh | bash

# guided — checks the device first, asks before each step
./setup.sh

# unattended, start to finish
./setup.sh bootstrap --auto

# individual components, and a diagnostic pass
./setup.sh install-build-tools 35.0.2
./setup.sh install-platform-tools 35.0.2
./setup.sh doctor

Installation order for a verified version: the checked-in artifacts/ tarball first (SHA256-verified against artifacts/SHA256SUMS), then a GitHub Release when one is registered in versions.json, otherwise a source build.
